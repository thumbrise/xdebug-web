# VISION

## Отладка PHP сложна. Попробуем сделать её простой.

### Проблема

Отладка PHP-приложений в современных средах разработки (Docker, WSL2, удалённые инфраструктуры) остаётся излишне сложной. Xdebug предоставляет необходимые возможности, но его интеграция с контейнерными рабочими процессами создаёт повторяющиеся проблемы:

- Настройка сети между контейнерами и хост-системой нестабильна (поведение `host.docker.internal` различается на разных платформах).
- Маппинг путей в IDE требует индивидуальной настройки и подвержен ошибкам.
- Ввод нового разработчика в проект начинается с отладки отладчика, а не с отладки приложения.
- Возможность отладки редко доступна в CI-пайплайнах или стейджинг-окружениях.
- Производительность Xdebug в окружениях, приближенных к продакшену, ограничивает его применение.

**Результат**: отладка остаётся локальной активностью, а не платформенной возможностью.

### Наше решение

**Xdebug-Web** - отладка как платформенный сервис.

Мы инкапсулируем сложность настройки отладки в автономный сервис. Вместо того чтобы требовать от разработчиков настройки IDE, управления маппингом путей и подбора переменных окружения, они просто запускают сервис и получают веб-интерфейс для отладки.

**Это не инструмент отладки. Это отладочный слой вашей платформы.**

### Как это работает

1. Лёгкий Go-сервис запускается рядом с вашим PHP-приложением (как правило, в той же Docker-сети).
2. Он слушает входящие DBGp-подключения от Xdebug или PHP Debugger.
3. При установлении сессии сервис управляет:
   - регистрацией точек останова;
   - выполнением шагов (шаг внутрь, обход, выход);
   - получением стека вызовов;
   - инспекцией переменных.
4. Состояние отладки передаётся в веб-интерфейс через WebSocket.
5. Разработчик открывает интерфейс в браузере и видит:
   - исходный код с текущей точкой выполнения;
   - иерархию стека вызовов;
   - локальные, глобальные и суперглобальные переменные;
   - элементы управления (продолжить, шаг, остановить).

**Никакой настройки IDE. Никакого маппинга путей. Достаточно браузера.**

---

### Что это решает

| Проблема                                            | Решение                                              |
|-----------------------------------------------------|------------------------------------------------------|
| Нестабильное подключение Xdebug в Docker-сетях      | Сервис работает внутри контейнерной сети             |
| Индивидуальные настройки IDE у разных разработчиков | Единый веб-интерфейс для всей команды                |
| Расхождения в маппинге путей                        | Общий том с кодом обеспечивает согласованность путей |
| Отладка недоступна в CI / стейджинге                | Сервис может быть развёрнут в любом окружении        |
| Производительность Xdebug                           | Совместимость с лёгким PHP Debugger (~1% оверхед)    |
| Высокий порог входа для новых разработчиков         | Интуитивный веб-интерфейс, не требующий обучения     |

### Влияние на опыт разработки

- **Нулевая конфигурация** - разработчик запускает `docker-compose up` и открывает интерфейс.
- **Единообразное окружение** - одинаковый интерфейс для всех членов команды независимо от их локальной настройки.
- **Портативность** - работает на Linux, macOS, Windows и в любом окружении с поддержкой Docker.
- **Быстрая обратная связь** - без переключения между IDE и инструментами отладки.
- **Прозрачность** - понятное отображение состояния отладки и потока выполнения.

### Влияние на переносимость

- **Не зависит от IDE** - работает с любой IDE или без неё.
- **Не зависит от ОС** - работает на Linux, macOS, Windows.
- **Не зависит от версии PHP** - работает с любой версией PHP, поддерживающей Xdebug.
- **Не зависит от окружения развёртывания** - подходит для локальной разработки, CI, стейджинга и (с осторожностью) продакшена.

### Философия

**Xdebug-Web рассматривает отладку как инфраструктуру, а не как личную настройку.**

Отладка должна быть первоклассной платформенной возможностью - такой же доступной и согласованной, как логирование, кеширование или доступ к базе данных. Отделяя отладку от индивидуальных инструментов разработчика, мы устраняем дрейф окружений и снижаем когнитивную нагрузку.

Мы не заменяем IDE. Мы предлагаем альтернативу, которая работает там, где отладка через IDE создаёт дополнительную сложность - особенно в контейнеризированных, распределённых или эфемерных средах.

**Отладка должна быть доступной, согласованной и переносимой.**

### План развития

1. Реализация минимально жизнеспособного продукта (MVP) с базовой функциональностью отладки.
2. Интеграция с PHP Debugger для снижения накладных расходов.
3. Поддержка одновременных сессий отладки.
4. Расширение возможностей интерфейса (условные точки останова, наблюдения, вычисление выражений).
5. Упаковка в Docker-образ и распространение через GitHub Packages / Docker Hub.
